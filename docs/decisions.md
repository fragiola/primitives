# Decisions

This library's guideline decisions, recorded on 2026-11-21 (Epic #5, Issue #2). Each one is
written in the Fragiola guidelines (`../guidelines`, paths below relative to it), and this page
mirrors them. The maintainer's decisions D1–D10 are in [`handoff.md`](handoff.md); they are not
repeated here.

| topic | decision | guideline page |
| --- | --- | --- |
| Library pattern | Core + adapters is the default. This library is the second pattern, **native primitives**: a spec per component, the framework-free DOM toolkit, one native implementation per framework, a styling layer for examples and tests, one conformance suite. No model API, no command bus, no stateful core (D3). | `architecture/native-primitives.md`, `decisions.md#library-pattern` |
| Part attribute | `data-primitives-part="<component>-<part>"` on every element (`"dialog-popup"`, `"menu-item"`, `"tabs-tab"`). State stays Base UI-style (`data-open`, `data-highlighted`, `data-popup-open`, ...) under the boolean rules: present or absent, never `"false"`. The POC's `data-<component>-part` is converted during the port. | `components/primitives.md#the-primitive-contract`, `decisions.md#np-part-attribute` |
| Toolkit re-export | The framework packages **do not** `export *` the toolkit (it would defeat D8). A toolkit type that appears in a component's API (`PlainDate`, `Side`, `Align`) is re-exported as a type from that component's entry. The toolkit is a regular `dependency`, published as the exact version. | `architecture/native-primitives.md#the-toolkit-boundary`, `decisions.md#np-toolkit-re-export` |
| Entries | One entry per component in every framework package, one per mechanism in the toolkit, and a root entry that only re-exports. tsdown multi-entry `exports` for the toolkit, React and Vue; one ng-packagr secondary entry point per component in Angular (as `../tree/packages/angular` does for features). Global providers (direction, locale) in their own entries. `check:package` checks every subpath. | `architecture/native-primitives.md#tree-shaking-a-hard-requirement`, `decisions.md#np-entries` |
| Source layout | Per-component folders inside the responsibility folders (`components/dialog/dialog-popup.tsx`) satisfy `repository.md#source-layout`. The toolkit has one folder per mechanism. Angular: each component's code lives in its ng-packagr secondary entry point's folder, organized like a `src/` (`packages/angular/dialog/directives/dialog-popup.directive.ts`, `dialog/inject/`), and the code the entries share in the `internal` entry (`packages/angular/internal/utils/`): ng-packagr compiles an entry point from its own folder (a file outside it fails with TS6059, `rootDir`), as Tree's feature entries do; `src/` holds only the root entry, which re-exports the components' entries (amended during Issue #3). | `architecture/native-primitives.md#source-layout`, `decisions.md#np-source-layout` |
| Tests | `conformance/` is the per-component referee: behaviour (with axe), contract and visual layers over the `fixtures/<framework>` apps, with one golden set made by React in CI. `examples/shared` holds the site examples' shared Playwright specs. No `apps/playground`. | `architecture/native-primitives.md#tests`, `decisions.md#np-tests` |
| Examples styling | Fragiola UI is Base UI + React, so it styles neither the Vue and Angular examples nor these primitives' examples. The examples and fixtures use the POC's recipes (Tailwind v4, keyed on `data-*`) on Fragiola UI's palette roles, with the five example themes (`light`, `dark`, `ide`, `paper`, `terminal`, shape tokens included). | `architecture/native-primitives.md#examples-styling`, `decisions.md#np-examples-styling` |
| Vue and Angular idioms | As the API mapping table of `spec/README.md`, cross-checked with `../tree` and `../splitter`. Vue: `as` or the `render` scoped slot, `class` / `style` values (state through `data-*` or the slot), template refs (`$el`), `v-model:<prop>`. Angular: attribute directives on the consumer's element, `state()` through `exportAs`, template reference variables, two-way `[(prop)]` bindings (an input with its `*Change` output, the shape of a `model()` input; the input plus output is used where a one-way binding must stay controlled). | `components/primitives.md#in-vue-and-angular`, `decisions.md#np-idioms` |
| Bundle guard | Per framework, a fixture app importing two components (Dialog and Tabs). It fails when any other component's code or an unused toolkit mechanism is in the output, by markers or source maps. Run by `pnpm build` and in CI; a test plants an import and sees it fail. | `architecture/native-primitives.md#tree-shaking-a-hard-requirement`, `architecture/features.md#guarantees-to-enforce`, `decisions.md#np-bundle-guard` |
| Modal overlays in the embeds | Each framework's embed host ports `../ui/examples/react/src/host/overlay-promotion.ts` (CONTRACT §5.4). The copyable example files never know about it. | `docs/site.md#examples`, `decisions.md#np-modal-overlays` |
| Site IA | "API: core (model, commands)" becomes "API: DOM toolkit (`@fragiola/primitives`)", plus one page per component: behaviour summary with the APG pattern, anatomy, per-framework usage, props, state and part attributes. Concepts: the pattern, the primitive contract, state and part attributes, tree-shaking, the behaviour rule (D4). | `docs/site.md#a-native-primitives-library`, `decisions.md#np-site-ia` |
| Runtime dependency | The toolkit keeps the POC's single runtime dependency, `@floating-ui/dom`, in the positioning entry only: the recorded exception to "zero runtime deps". | `architecture/native-primitives.md#the-toolkit-boundary`, `decisions.md#np-runtime-dependency` |
| Site contract | Target `../www/CONTRACT.md` v1.7 (`CONTRACT_VERSION` `"1.7"`), the current version. The dev port is 5191 (`site:dev`); the library is not in `../www/projects.json` until the maintainer validates it. | `docs/site.md#what-a-new-library-provides`, `decisions.md#np-contract-version` |

## Overlays: details decided during Epic #7 (Issue #6)

Questions the handoff §3, the APG and Base UI did not settle, decided by the Epic's stop condition
(take the APG-closest option, record it in the spec and here).

| topic | decision | alternatives discarded | spec |
| --- | --- | --- | --- |
| How "unless the press landed on a focusable element" is checked | The toolkit's overlay session waits until the outside press has ended (pointerup, then a task, for touch), then returns focus only when focus is on the body: whatever the press focused, it keeps (`returnFocus.whenUnfocused`). A press inside a dialog's popup (`tabindex="-1"`) therefore keeps focus on that popup | testing the press target for focusability at pointerdown (misses a focusable ancestor and the browser's own focus rules) | `popover.md` "Focus", `dialog.md` `/dialog/nested-popover` |
| The focus an outside press gives | Not reported again as `focus-out`: the press already dismissed the overlay with `outside-press` | reporting both reasons | `popover.md` "Focus" |
| `data-side` of a flipped side | Named as it was asked: a flipped `inline-end` reports `inline-start`, a flipped `right` reports `left` (Base UI) | always logical, or always physical | `popover.md` "Positioning", `README.md` |
| How a modal menu blocks the outside pointer | The body stops taking pointer events (`@fragiola/primitives/inert`, `blockOutsidePointer`) and the trigger and every level's positioner take them back (`pointer-events: auto`, structural inline style): no extra backdrop element in the DOM | an invisible backdrop part (one more element in every framework's DOM and the goldens); capture listeners that cancel events (they cannot stop hover) | `menu.md` "Modal" |
| A modal menu's outside press and focus | It closes every level and focus returns to the trigger (the press reaches nothing to focus); the keyboard is unchanged (no trap, no inert page: Tab still closes and moves on) | trapping focus like a dialog (the APG menu has no trap) | `menu.md` "Modal", "Focus" |
| A submenu and `modal` | A submenu follows its root menu; `SubmenuRoot` takes no `modal` (Angular's shared `MenuRoot` directive accepts the input and ignores it on a submenu) | a per-level option | `menu.md` "API" |
| A non-modal menu's outside press | Unchanged from the POC: no focus return, the press reaches the page | returning focus like the Popover (not in §3) | `menu.md` "Focus" |

## The Field layer: details decided during Epic #26 (Issues #23–#25)

Stage 1's first Epic: Field to production, Fieldset, Form, every form control in a Field, Slider's
Label and Value, the pickers' form support, the direction provider and the render utilities. No
rule of the handoff (D1–D10, §3, §4) changed; the APG has no field, fieldset or form pattern, so
Base UI decides (D4) unless a row says otherwise.

| topic | decision | alternatives discarded | spec |
| --- | --- | --- | --- |
| Async `validate` races | Latest wins: every validation starts a run, a run that resolves after a newer one started is dropped. While the latest run is pending the field keeps what it showed; a native error is shown at once and the promise not awaited; a rejected promise is no message | showing "valid" while pending; a debounce (Base UI's `validationDebounceTime`, out of scope) | `field.md` "Async validation" |
| A value already validated | The field reuses the last resolved run's messages for the same value instead of calling `validate` again, so a submission of an unchanged value is blocked by them. A submission never waits for a pending run (Base UI) | validating again on submit (Base UI: a taken name submits while its check runs again) | `field.md` "Async validation" |
| `Field.Error`'s `match` | A `ValidityState` key, `true`, or a function of the validity (this library's addition, the Epic's scope) | keys only (Base UI) | `field.md` "API" |
| Server errors | Shown by an Error with no `match` (or `true`); a key or a function matches the validity, which server errors are not part of (Base UI). A disabled field shows none (the POC's rule, kept) | Base UI keeping the app's invalid state on a disabled field | `field.md` "Validation" |
| Where Fieldset's and Form's contexts live | In the field component's folder (Angular: exported by `/field` as its lower layer): `/fieldset` and `/form` are built on `/field`, never the other way round, so a form control still pulls only Field (`ENTRY_DEPENDENCIES`) | contexts in their own components' folders (every control would pull Fieldset and Form) | `fieldset.md`, `form.md` |
| Fieldset's Legend | A `div` naming the `fieldset` through `aria-labelledby` (Base UI) | a native `<legend>` (sits on the border, resists styling) | `fieldset.md` "Anatomy" |
| How the Form blocks a submission | `novalidate`; a capture `submit` listener on the form (the toolkit's `guardFormSubmit`) validates every registered field, and on an invalid one calls `preventDefault` and `stopImmediatePropagation`, then focuses the first invalid field's control in document order (a text input's text selected). The consumer's own native `submit` listener (React `onSubmit`, Vue `@submit`, Angular `(submit)`) therefore runs only for a submission that goes on, the same in every framework | a custom `onFormSubmit` event (Base UI; out of scope); letting the browser's validation block it (cannot validate a Slider or a CheckboxGroup, shows the browser's bubble) | `form.md` "A submission" |
| `onClearErrors` | Called with the errors left when a field's change drops its key; the Form hides them at once from its own copy, which a new `errors` object replaces (Base UI clears silently) | requiring the consumer to pass the new object back | `form.md` "API" |
| Server errors after a submission | Focus moves to the first invalid field when `errors` changes after a submission went on (Base UI) | no focus move | `form.md` |
| The failed validation of several required controls | A form bridge focuses its primitive only when its hidden input is the form's first invalid control: the browser fires `invalid` on every one, and the last bridge took the focus (found with two required pickers) | | `README.md` "Forms" |
| CheckboxGroup in a Field | The group is the field's control: named and described by the field, `aria-invalid` on the `group`; its checkboxes take the field's `name` and do not register; focus target its first enabled checkbox; no validated element (`validate` decides; a Form blocks a submission, a native form cannot) (Base UI) | the first checkbox's hidden input as the validated element | `checkbox.md`, `field.md` |
| The pickers' form value | One visually hidden text input (`required` can block a native submission): a DatePicker submits the ISO date, a DateRangePicker **one** entry, the ISO 8601 interval `start/end`, empty until both ends are chosen | two entries, or React Aria's `startName` / `endName` | `calendar.md` "Forms" |
| A read-only picker | Its trigger still opens the popup; the bound calendar is read-only; the value still submits | a disabled trigger | `calendar.md` "Forms" |
| A picker's Trigger in a Field | `aria-labelledby` lists the field's label **then the Trigger itself**: its visible text (the chosen date) stays in its name (WCAG 2.5.3, axe `label-content-name-mismatch`, which the label alone failed in every framework). A press on the label only focuses the Trigger: a click would open the popup, which takes the focus | the label alone (fails 2.5.3); `<label for>` alone (the same name) | `field.md` "Integration contract", "Focus" |
| Slider's Value and `aria-valuetext` with a range | The formatted values joined with `" – "` (Base UI's separator, punctuation); a thumb's `aria-valuetext` is its formatted value alone, without Base UI's English `" start range"` / `" end range"` (no text, spec/README.md) | Base UI's suffixes | `slider.md` "API" |
| Slider's default `locale` | The runtime's (`Intl.NumberFormat(undefined)`, Base UI); a server render passes `locale` | the calendars' document-`lang` rule (a mounted-locale step per framework for one formatting option) | `slider.md` "API" |
| A Slider Label press | Focuses the first thumb (Base UI; a `div` has no `for`) | | `slider.md` |
| The Slider's form reset | Every framework's Slider now returns to its default on a form reset (it did not; the new reset checks found it), through the form bridge on its first hidden input | | `README.md` "Forms" |
| The direction provider | Its own entry `/direction` in every framework (D8), rendering nothing and setting no `dir`; Angular also `provideDirection()`.
