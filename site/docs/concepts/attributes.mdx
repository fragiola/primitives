---
title: Part and state attributes
description: How to select and style every part with data-primitives-part, and its state with data-* and ARIA attributes, the same in every framework.
---

Every element a primitive renders says which part it is, and its state is attributes: select and
style them, never class names the library does not have.

## The part attribute

Every element carries `data-primitives-part="<component>-<part>"`:

| element | attribute |
| --- | --- |
| a dialog's trigger | `data-primitives-part="dialog-trigger"` |
| a dialog's popup | `data-primitives-part="dialog-popup"` |
| an alert dialog's popup (Dialog's part, named by its root) | `data-primitives-part="alert-dialog-popup"` |
| a context menu's item (Menu's part, named by its root) | `data-primitives-part="context-menu-item"` |
| a tab | `data-primitives-part="tabs-tab"` |
| the tab indicator | `data-primitives-part="tabs-indicator"` |
| a combobox's hidden inputs | `data-primitives-part="combobox-hidden-input"` |
| a calendar's cell, and a range calendar's | `data-primitives-part="calendar-cell"`, `"range-calendar-cell"` |

One attribute for the whole library, since many components have parts of the same name. Your
tests, styles and tools can rely on it in every framework.

## State attributes

A boolean state is an attribute that is **present** (with an empty value) or **absent**, never
`"false"`, so `[data-open]` and Tailwind's `data-open:` variant just work.

| attribute | on |
| --- | --- |
| `data-open` | an open overlay (a popup, its positioner, its arrow, a dialog's backdrop and viewport); an open collapsible, accordion item and their parts |
| `data-closed` | a rendered overlay part that is not open (its exit runs, or the Portal's `keepMounted` keeps it, `hidden`); a closed collapsible, accordion item and their parts (with `data-open`: exactly one is present) |
| `data-panel-open` | a collapsible's or an accordion's trigger while its panel is open |
| `data-popup-open` | a trigger while its overlay is open: the active one of several detached triggers only (a Select's or a date picker's trigger, a Combobox's or an Autocomplete's input, input group and trigger too, a context menu's area) |
| `data-starting-style` | an element that just mounted, for one frame: transition from it |
| `data-ending-style` | an element whose exit animation runs; it unmounts (or is hidden) once its animations end: an overlay, a tabs panel, a collapsible or accordion panel |
| `data-selected` | a selected tab and its panel, a selected select, combobox or listbox option, a chosen calendar date |
| `data-checked`, `data-unchecked`, `data-indeterminate` | a checkbox's state (exactly one is present) and its indicator; a switch's and a radio's `data-checked` or `data-unchecked`, on its thumb or indicator too; a menu checkbox or radio item's, and its indicator's |
| `data-indeterminate`, `data-progressing`, `data-complete` | a progress bar's status, on every part (exactly one is present): no value, a value below `max`, `max`; `data-complete` also on every part of an OTP field whose code is complete |
| `data-scrubbing` | every part of a number field while its scrub area scrubs |
| `data-readonly` | a read-only number field's or OTP field's parts (and a read-only calendar or switch) |
| `data-pressed` | a pressed toggle |
| `data-multiple` | a toggle group or a listbox with `multiple` |
| `data-placeholder` | a Select showing its placeholder |
| `data-empty` | a combobox's or an autocomplete's list with no item |
| `data-dragging` | a slider while a pointer drags a thumb |
| `data-index` | a slider thumb's value index; an OTP field slot's index (a value) |
| `data-required` | a required checkbox, switch or radio group, and its radios; every part of a required number field or OTP field |
| `data-invalid`, `data-valid` | a field that shows an error, or that validated and is valid |
| `data-dirty`, `data-touched`, `data-filled`, `data-focused` | a field whose value changed, whose control lost focus once, whose value is not empty, whose control has focus; `data-filled` also on an OTP field slot that holds a character |
| `data-highlighted` | the menu item, select, combobox or autocomplete option the keyboard or the pointer points at; a listbox's focused option |
| `data-instant` | a tooltip that opened with no delay (focus, or a hand-off in its group) |
| `data-nested` | a submenu's positioner and popup; a nested dialog's popup, backdrop and viewport (a dialog or alert dialog inside another's popup) |
| `data-nested-dialog-open` | a dialog's popup, backdrop and viewport while a dialog nested in it is open |
| `data-side` | the side a positioned overlay ended up on (a value: `top`, `bottom`, `inline-start`, `inline-end`, `left`, `right`, named as it was asked) |
| `data-align` | `start`, `center` or `end` (a value) |
| `data-disabled` | a disabled part |
| `data-orientation` | `horizontal` or `vertical` (a value): tabs, an accordion, a slider, a radio group given an `orientation`, a separator, a toggle group, a toolbar and its parts, a menubar |
| `data-activation` | `automatic` or `manual` on tabs (a value) |
| `data-activation-direction` | where the newly selected tab sits from the previous one, on every tabs part (a physical value: `left`, `right`, `up`, `down`, `none`) |
| `data-today`, `data-outside-month`, `data-unavailable` | a calendar cell of today, of another month's day, of a date the app marked unavailable |
| `data-range-start`, `data-range-end`, `data-in-range`, `data-range-preview` | a range calendar's cells: the range's ends, its dates, the dates of a range being chosen |
| `data-readonly` | a read-only calendar, a read-only switch and its thumb |

One CSS variable carries the depth of nested dialogs: a dialog's popup has the inline style
`--nested-dialogs: <n>`, the number of open dialogs nested below it as a chain (`0` when none), to
scale or offset the parent (`scale: calc(1 - 0.05 * var(--nested-dialogs))`).

ARIA carries the rest: `aria-expanded`, `aria-selected`, `aria-checked`, `aria-pressed`, `aria-invalid`,
`aria-activedescendant`, `aria-modal`, `aria-controls`, `aria-current`, `aria-readonly`, `aria-valuenow`
and `aria-valuetext`.

## An enter and exit transition

```css
[data-primitives-part="dialog-popup"] {
    transition: opacity 150ms, scale 150ms;
}
[data-primitives-part="dialog-popup"][data-starting-style],
[data-primitives-part="dialog-popup"][data-ending-style] {
    opacity: 0;
    scale: 0.95;
}
```

The popup stays mounted while its exit transition runs, and unmounts when it ends (or, with the
Portal's `keepMounted`, is hidden with `data-closed`). `onOpenChangeComplete(open)` reports the end
of each transition.
