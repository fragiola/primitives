title: CommandVirtual
description: A Command List over thousands of actions that renders only the shown Items in view, the keys and the highlight reaching every match.
---

A [Command](/docs/api/command) for a long list of actions: **CommandVirtual.List** replaces the
Command's List, filters its `items` with the Root's text and `filter`, and renders only the shown
Items in view (with 10 000 items, a few dozen options in the DOM), while the keys, the highlight
on the best match and `aria-activedescendant` reach every match. It is opt-in, in an entry of its
own, `/command-virtual`: a Command that does not use it ships no virtualizer.

The APG has no virtual list pattern; it only says that a set whose options are not all in the DOM
gives each option `aria-setsize` and `aria-posinset`. Everything else is the
[Command](/docs/api/command)'s (the APG [combobox pattern](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/)): a virtual list
behaves as the same list rendered whole.

## Behaviour

- **The Command's part**: the List is a Command List (`data-primitives-part="command-list"`, the
  same role and state attributes, `data-empty` and `data-loading` included), so a Command recipe
  and its selectors apply. Its options are `Command.Item`s that you render for each row in view.
- **It filters its `items`**, `{ value, keywords?, disabled? }` (more fields allowed), with the
  Root's text and `filter` (the toolkit's `commandMatches`): only the matching entries are rows.
  No groups.
- **Only the rows in view are rendered**, plus `overscan` rows beyond each end and the **pinned**
  rows: the first and last matches, the highlighted one with its neighbours and the best match. So
  the arrows, Home and End and the highlight behave as with every Item rendered.
- **The place in the set**: each rendered option has `aria-setsize` (the number of matching
  entries), `aria-posinset` (its index + 1) and `data-index`.
- **Sizes, loading**: `itemSize`, `measure`, `overscan`, `loading` and `onLoadMore` as every
  virtual list's ([ListboxVirtual](/docs/api/listbox-virtual)); pages from a loader come through
  the [async list](/docs/api/async-list).

### The row style

The rows keep the list's flow layout: no wrapper and no spacer element. Each rendered option gets,
inline, the room of the unrendered rows before it as `margin-block-start` (the last one, the room
after it as `margin-block-end`), `flex-shrink: 0` and `overflow-anchor: none`. So lay the options
out in a **flex or grid column** with **no margin of their own**, make the **List the scroll
container** (a height and `overflow-y: auto` on it), and set `itemSize` to the typical row height.

## Anatomy

The [Command](/docs/api/command)'s parts, the List replaced:

| part | element | `data-primitives-part` | role |
| --- | --- | --- | --- |
| List | `div` | `command-list` | the `listbox`, a Command List that renders the matching entries in view |
| (options) | `div` | `command-item` | your `Command.Item` for each row in view |

## Usage

<Framework name="react">

```tsx
import { Command, CommandVirtual } from "@fragiola/primitives-react/command-virtual";

<Command.Root>
    <Command.Input aria-label="Command" />
    <Command.Empty>No results.</Command.Empty>
    <CommandVirtual.List items={ACTIONS} className="flex h-80 flex-col overflow-y-auto">
        {(entry) => (
            <Command.Item value={entry.value} disabled={entry.disabled} onSelect={run}>
                {entry.value}
            </Command.Item>
        )}
    </CommandVirtual.List>
</Command.Root>;
```

</Framework>

<Framework name="vue">

```vue
<template>
    <Command.Root>
        <Command.Input aria-label="Command" />
        <Command.Empty>No results.</Command.Empty>
        <CommandVirtual.List :items="ACTIONS" class="flex h-80 flex-col overflow-y-auto">
            <template #default="{ entry }: { entry: Action }">
                <Command.Item :value="entry.value" :disabled="entry.disabled" @select="run">{{ entry.value }}</Command.Item>
            </template>
        </CommandVirtual.List>
    </Command.Root>
</template>
```

`Command` and `CommandVirtual` both come from `@fragiola/primitives-vue/command-virtual`; the
default scoped slot gets `{ entry, index }` for each matching entry in view.

</Framework>

<Framework name="angular">

```ts
@Component({
    imports: [CommandRoot, CommandInput, CommandEmpty, CommandVirtualList, CommandVirtualRow, CommandItem],
    template: `
        <div commandRoot>
            <input commandInput aria-label="Command" />
            <div commandEmpty>No results.</div>
            <div commandVirtualList #list="commandVirtualList" [items]="actions" class="flex h-80 flex-col overflow-y-auto">
                @for (row of list.rows(); track row.index) {
                    <div commandItem [commandVirtualRow]="row" [value]="row.item.value" (itemSelect)="run($event.value)">{{ row.item.value }}</div>
                }
            </div>
        </div>
    `,
})
export class Palette {
    protected readonly actions = ACTIONS;
}
```

`[commandVirtualList]` is a `[commandList]` (a host directive); its `rows()` (through `exportAs`)
are the matching entries to render, each `[commandItem]` with the `[commandVirtualRow]` of its
row. Every directive comes from `@fragiola/primitives-angular/command-virtual`, which re-exports
the Command entry.

</Framework>

## Props

Every part also takes what the [primitive contract](/docs/concepts/primitive-contract) gives:
`render` (Vue: `as` and the `render` slot), a class and a style, a ref, and any attribute, which
it forwards. The names below are React's; Vue binds them the same way (`@load-more`), and Angular
as inputs and outputs (`(loadMore)`). The other parts are the [Command](/docs/api/command)'s.

### List

| prop | type | default | description |
| --- | --- | --- | --- |
| `items` | `{ value, keywords?, disabled? }[]` | | required: the entries, filtered with the Root's text and `filter` |
| `itemSize` | `number \| (index: number) => number` | `36` | a row's size in px before it is measured (every row's with `measure` off): the typical row height |
| `measure` | `boolean` | `true` | measure the rendered rows; `false`: fixed sizes |
| `overscan` | `number` | `4` | the rows rendered beyond each end of the view |
| `loading` | `boolean` | `false` | the list is loading: `data-loading`, `aria-busy="true"` |
| `onLoadMore` | `() => void` | | the last row came into view while not `loading`: load the next page (Vue `@load-more`, Angular `(loadMore)`) |

React's `children` and Vue's default slot render each matching entry in view, with its index (an
Angular template renders `rows()`).

## State and part attributes

Everything of the [Command](/docs/api/command)'s List and Items, plus:

| part | attributes |
| --- | --- |
| each rendered option | `aria-setsize` (the number of matching entries), `aria-posinset` (its index + 1), `data-index` (its index); inline `margin-block-start` / `margin-block-end` when unrendered rows come before / after it, `flex-shrink: 0`, `overflow-anchor: none` |

## Keyboard

The [Command](/docs/api/command)'s keys, over every matching entry: the highlighted Item is
rendered and scrolled into view.
