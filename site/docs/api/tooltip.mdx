A short description of a control, shown while the control is hovered or keyboard-focused. It
never takes focus and holds nothing interactive. The primitive wires it itself: the popup is a
`tooltip` and the trigger's `aria-describedby` points at it, so what it says is the control's
accessible **description** (the control still needs its own name). It follows the WAI-ARIA APG
[tooltip pattern](https://www.w3.org/WAI/ARIA/apg/patterns/tooltip/), and stays open while hovered
(WCAG 1.4.13).

<Example id="tooltip" />

## Behaviour

- **Hover**: the pointer entering the Trigger opens it after `delay` (reason `trigger-hover`);
  leaving before then cancels. A touch tap never opens it.
- **Hoverable**: leaving the Trigger closes it after `closeDelay`, unless the pointer moves onto
  the popup (across the gap): it stays open while hovered, and closes when the pointer leaves both,
  or leaves the window (or the iframe the page is in) at once.
- **Keyboard**: keyboard focus on the Trigger opens it at once (`trigger-focus`, `data-instant`);
  blur closes it. Escape closes it (`escape-key`), keeps focus on the trigger, and stops there: an
  enclosing dialog stays open.
- **Press**: a press on the Trigger closes it (`trigger-press`); it does not reopen until the
  pointer leaves and comes back.
- **Delay group**: within one Provider, one tooltip is open at a time. Moving from an open
  tooltip's trigger to another one opens it at once (`data-instant`), also within `timeout` ms of
  the last close.
- **Positioning**: as the [Popover's](/docs/api/popover), from the Trigger, on the `top` by
  default.
- **Detached triggers**: Triggers anywhere in the page show the same Root through a `handle`,
  each with a `payload` the content reads ([detached triggers](/docs/guides/detached-triggers)).
  Hovering another trigger of the open tooltip moves it there at once.
- **Lifecycle**: `onOpenChange` is called before the change (`details.cancel()` keeps it as it
  is, [change details](/docs/concepts/primitive-contract)), `onOpenChangeComplete(open)` reports
  the end of each transition, the actions `close()` and `unmount()` act from code, and the
  Portal's `keepMounted` keeps the Positioner in the page while closed (`hidden`, `data-closed`).

## Anatomy

| part | element | `data-primitives-part` | role |
| --- | --- | --- | --- |
| Provider | none | | a delay group: shared delays and the instant hand-off |
| Root | none | | holds the state |
| Trigger | `button` | `tooltip-trigger` | the described control, and the anchor |
| Portal | none | | moves the Positioner to the end of `body` |
| Positioner | `div` | `tooltip-positioner` | places the popup next to the trigger |
| Popup | `div` | `tooltip-popup` | the tooltip |
| Arrow | `div` | `tooltip-arrow` | points at the trigger (optional) |

## Usage

<Framework name="react">

```tsx
import { Tooltip } from "@fragiola/primitives-react/tooltip";

<Tooltip.Provider delay={500}>
    <Tooltip.Root>
        <Tooltip.Trigger>Bold</Tooltip.Trigger>
        <Tooltip.Portal>
            <Tooltip.Positioner sideOffset={8}>
                <Tooltip.Popup>
                    <Tooltip.Arrow />
                    Bold (Ctrl+B)
                </Tooltip.Popup>
            </Tooltip.Positioner>
        </Tooltip.Portal>
    </Tooltip.Root>
</Tooltip.Provider>;
```

</Framework>

<Framework name="vue">

```vue
<script setup lang="ts">
import { Tooltip } from "@fragiola/primitives-vue/tooltip";
</script>

<template>
    <Tooltip.Provider :delay="500">
        <Tooltip.Root>
            <Tooltip.Trigger>Bold</Tooltip.Trigger>
            <Tooltip.Portal>
                <Tooltip.Positioner :side-offset="8">
                    <Tooltip.Popup>
                        <Tooltip.Arrow />
                        Bold (Ctrl+B)
                    </Tooltip.Popup>
                </Tooltip.Positioner>
            </Tooltip.Portal>
        </Tooltip.Root>
    </Tooltip.Provider>
</template>
```

</Framework>

<Framework name="angular">

```ts
@Component({
    imports: [TooltipProvider, TooltipRoot, TooltipTrigger, TooltipPortal, TooltipPositioner, TooltipPopup, TooltipArrow],
    template: `
        <ng-container tooltipProvider [delay]="500">
            <ng-container tooltipRoot>
                <button tooltipTrigger>Bold</button>
                <ng-container *tooltipPortal>
                    <div tooltipPositioner [sideOffset]="8">
                        <div tooltipPopup><div tooltipArrow></div>Bold (Ctrl+B)</div>
                    </div>
                </ng-container>
            </ng-container>
        </ng-container>
    `,
})
export class BoldButton {}
```

`injectTooltip()` gives a child component the tooltip's state.

</Framework>

## Props

Every part also takes what the [primitive contract](/docs/concepts/primitive-contract) gives:
`render` (Vue: `as` and the `render` slot), a class and a style, a ref, and any attribute, which
it forwards. The names below are React's; Vue binds them the same way (`v-model:open`,
`@open-change`), and Angular as inputs and outputs (`[(open)]`, `(openChangeDetails)`).

### Provider

| prop | type | default | description |
| --- | --- | --- | --- |
| `delay` | `number` | `600` | ms before a hovered trigger opens its tooltip |
| `closeDelay` | `number` | `0` | ms before a tooltip closes once the pointer left |
| `timeout` | `number` | `400` | ms after a close during which another tooltip of the group opens at once |

### Root

| prop | type | default | description |
| --- | --- | --- | --- |
| `open` | `boolean` | | the open state, controlled |
| `defaultOpen` | `boolean` | `false` | the initial open state, uncontrolled |
| `onOpenChange` | `(open: boolean, details: OpenChangeDetails) => void` | | every change, with its reason (`trigger-hover`, `trigger-focus`, `trigger-press`, `escape-key`); called before the change, `details.cancel()` stops it |
| `onOpenChangeComplete` | `(open: boolean) => void` | | once an opening or a closing has finished its transitions (not on the first render, nor for an exit a reopening interrupted) |
| `actionsRef` (react) | `{ current: OverlayActions \| null }` | | receives `close()` (reason `imperative-action`) and `unmount()` (ends an exit now); Vue exposes them on the Root's template ref, Angular as the root directive's methods |
| `handle` | `TooltipHandle<Payload>` | | connects Triggers rendered outside the Root ([detached triggers](/docs/guides/detached-triggers)) |
| `triggerId` | `string \| null` | | the active trigger's id, controlled together with `open` |
| `defaultTriggerId` | `string \| null` | `null` | the initial active trigger, uncontrolled |
| `delay` | `number` | the Provider's, else `600` | ms before a hovered trigger opens it |
| `closeDelay` | `number` | the Provider's, else `0` | ms before it closes once the pointer left |
| `disabled` | `boolean` | `false` | a disabled tooltip never opens |

### Trigger

| prop | type | default | description |
| --- | --- | --- | --- |
| `handle` | `TooltipHandle<Payload>` | | the handle of a Root this Trigger opens from anywhere, outside it |
| `payload` | `Payload` | | what the Root's content receives while this Trigger is the active one |
| `id` | `string` | generated | the Trigger's id: `triggerId` and the handle's `open(id)` name it |

### Portal

| prop | type | default | description |
| --- | --- | --- | --- |
| `container` (react, vue) | `Element` | `document.body` | where the Positioner goes |
| `keepMounted` (react, vue) | `boolean` | `false` | keep the content rendered while closed (before the first opening and after an exit), `hidden` and `data-closed`; reopening shows the same elements |
| `options` (angular) | `Element \| { container?, keepMounted? }` | `{}` | the same two options: `*tooltipPortal="{ keepMounted: true }"`, or `*tooltipPortal="element"` for a container alone |

### Positioner

| prop | type | default | description |
| --- | --- | --- | --- |
| `side` | `"top" \| "bottom" \| "inline-start" \| "inline-end" \| "left" \| "right"` | `"top"` | the side of the trigger; `inline-*` follow the direction |
| `align` | `"start" \| "center" \| "end"` | `"center"` | the alignment along that side |
| `sideOffset` | `number` | `0` | the distance from the trigger, in px |
| `alignOffset` | `number` | `0` | the shift along the trigger's edge, in px |
| `collisionPadding` | `number` | `8` | the space kept from the viewport's edges, in px |
| `anchor` | `Element` | the trigger | the element to place the popup next to |

### Popup

No props of its own.

### Arrow

No props of its own.

## State and part attributes

| part | attributes |
| --- | --- |
| Trigger | `aria-describedby` (the popup while open, added to the consumer's own), `data-popup-open` |
| Positioner | `role="presentation"`, `data-side`, `data-align`, `data-open` / `data-closed`; the anchor CSS variables, as the Popover's; `hidden` while kept mounted and closed |
| Popup | `role="tooltip"`, an `id`, `data-side`, `data-align`, `data-open` / `data-closed`, `data-instant` (opened with no delay), `data-starting-style`, `data-ending-style` |
| Arrow | `aria-hidden="true"`, `data-side`, `data-align` |

## Keyboard

| key | action |
| --- | --- |
| Tab onto the Trigger | opens at once |
| Tab away | closes |
| Escape | closes, focus stays on the trigger |
