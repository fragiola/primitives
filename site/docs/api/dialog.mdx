A window over the page: it takes focus, keeps it inside, makes the rest of the page inert and
stops it scrolling, and gives focus back when it closes. It follows the WAI-ARIA APG
[modal dialog pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/). Non-modal floating
content is a [Popover](/docs/api/popover); a dialog the user must answer, never dismissed from
outside, is an [AlertDialog](/docs/api/alert-dialog).

## Behaviour

- **Open**: a press on the Trigger (Enter and Space, as any button). Focus moves to
  `initialFocus`, else the first tabbable element of the popup, else the popup itself.
- **Inside**: Tab and Shift+Tab wrap inside the popup; everything outside the portal is inert,
  and the page does not scroll (its scrollbar gutter is kept, so nothing shifts).
- **Close**: Escape (reason `escape-key`), a press outside the popup (`outside-press`), a Close
  part (`close-press`) or the Trigger again (`trigger-press`). Focus moves to `finalFocus`, else
  the trigger, else the element focused before it opened.
- **Change details**: `onOpenChange(open, details)` is called **before** the state changes, with
  the `reason`, the DOM `event` and the `trigger`; `details.cancel()` keeps the dialog as it is (it
  keeps working, focus and inertness included). A close of the handle or of the actions has the
  reason `imperative-action` and returns focus as `none` does.
- **Layers**: the dialog is a layer of the [nested overlay tree](/docs/guides/nested-overlays).
  Escape closes the newest layer only; a press inside the dialog closes the overlays opened from
  it, not the dialog; closing the dialog closes them all (reason `none`).
- **Nested dialogs**: a Dialog whose Root is inside another dialog's Popup is nested: its parts
  carry `data-nested`, the parent's `data-nested-dialog-open`, and the parent Popup's
  `--nested-dialogs` counts the open dialogs below it (`2` for a child with its own child open,
  `0` when none), so a recipe can scale or offset it. A nested Backdrop renders nothing unless
  `forceRender`. A press on a nested dialog's Viewport outside its Popup closes that dialog only.
- **Detached triggers**: Triggers anywhere in the page open the same Root through a `handle`, each
  with a `payload` the content reads ([detached triggers](/docs/guides/detached-triggers)). Only
  the active trigger reports the open state, and focus returns to it. The handle's
  `open(triggerId)`, `openWithPayload(payload)` and `close()` act from code (reason
  `imperative-action`), `isOpen` reads the state; a call with no Root attached does nothing.
- **Animation and lifecycle**: the Backdrop, the Viewport and the Popup carry
  `data-starting-style` on their first frame and `data-ending-style` while closing, and unmount
  when their animations end; `onOpenChangeComplete(open)` reports the end of each transition. With
  the Portal's `keepMounted`, they stay in the page while closed, `hidden` and `data-closed`.

## Anatomy

| part | element | `data-primitives-part` | role |
| --- | --- | --- | --- |
| Root | none | | holds the state |
| Trigger | `button` | `dialog-trigger` | opens the dialog |
| Portal | none | | moves the Backdrop, the Viewport and the Popup to the end of `body` |
| Backdrop | `div` | `dialog-backdrop` | covers the page (optional; a nested dialog's renders nothing unless `forceRender`) |
| Viewport | `div` | `dialog-viewport` | a full-page container that positions the Popup (optional, `role="presentation"`) |
| Popup | `div` | `dialog-popup` | the dialog |
| Title | `h2` | `dialog-title` | names the dialog |
| Description | `p` | `dialog-description` | describes the dialog |
| Close | `button` | `dialog-close` | closes the dialog |

## Usage

<Framework name="react">

```tsx
import { Dialog } from "@fragiola/primitives-react/dialog";

<Dialog.Root onOpenChange={(open, { reason }) => console.log(open, reason)}>
    <Dialog.Trigger>Edit profile</Dialog.Trigger>
    <Dialog.Portal>
        <Dialog.Backdrop />
        <Dialog.Viewport>
            <Dialog.Popup>
                <Dialog.Title>Edit profile</Dialog.Title>
                <Dialog.Description>Change how others see you.</Dialog.Description>
                <Dialog.Close>Close</Dialog.Close>
            </Dialog.Popup>
        </Dialog.Viewport>
    </Dialog.Portal>
</Dialog.Root>;
```

Controlled: `open` and `onOpenChange`, with `useState`. The actions: `actionsRef={ref}`, then
`ref.current?.close()`. Detached triggers: `const handle = Dialog.createHandle<User>()`,
`<Dialog.Trigger handle={handle} payload={user}>` anywhere, and the Root's children as a function
`{({ payload }) => ...}`.

</Framework>

<Framework name="vue">

```vue
<script setup lang="ts">
import { Dialog } from "@fragiola/primitives-vue/dialog";
import { ref } from "vue";

const open = ref(false);
</script>

<template>
    <Dialog.Root v-model:open="open" @open-change="(open, { reason }) => console.log(reason)">
        <Dialog.Trigger>Edit profile</Dialog.Trigger>
        <Dialog.Portal>
            <Dialog.Backdrop />
            <Dialog.Viewport>
                <Dialog.Popup>
                    <Dialog.Title>Edit profile</Dialog.Title>
                    <Dialog.Description>Change how others see you.</Dialog.Description>
                    <Dialog.Close>Close</Dialog.Close>
                </Dialog.Popup>
            </Dialog.Viewport>
        </Dialog.Portal>
    </Dialog.Root>
</template>
```

The Root's template ref exposes the actions (`close()`, `unmount()`); its default scoped slot gives
the active trigger's payload (`v-slot="{ payload }"`); `@open-change-complete` reports the end of
each transition.

</Framework>

<Framework name="angular">

```ts
@Component({
    imports: [DialogRoot, DialogTrigger, DialogPortal, DialogBackdrop, DialogViewport, DialogPopup, DialogTitle, DialogDescription, DialogClose],
    template: `
        <ng-container dialogRoot #dialog="dialogRoot" [(open)]="open" (openChangeDetails)="log($event.details.reason)">
            <button dialogTrigger>Edit profile</button>
            <ng-container *dialogPortal>
                <div dialogBackdrop></div>
                <div dialogViewport>
                    <div dialogPopup>
                        <h2 dialogTitle>Edit profile</h2>
                        <p dialogDescription>Change how others see you.</p>
                        <button dialogClose>Close</button>
                    </div>
                </div>
            </ng-container>
        </ng-container>
    `,
})
export class EditProfile {
    protected readonly open = signal(false);
}
```

`*dialogPortal="element"` portals into another container, `*dialogPortal="{ keepMounted: true }"`
keeps the content while closed. `#dialog="dialogRoot"` gives the actions (`dialog.close()`,
`dialog.unmount()`) and the active trigger's `dialog.payload()`; `(openChangeComplete)` reports
the end of each transition. `injectDialog()` gives a child component the dialog's state.

</Framework>

## Props

Every part also takes what the [primitive contract](/docs/concepts/primitive-contract) gives:
`render` (Vue: `as` and the `render` slot), a class and a style, a ref, and any attribute, which
it forwards. The names below are React's; Vue binds them the same way (`v-model:open`,
`@open-change`), and Angular as inputs and outputs (`[(open)]`, `(openChangeDetails)`).

### Root

| prop | type | default | description |
| --- | --- | --- | --- |
| `open` | `boolean` | | the open state, controlled |
| `defaultOpen` | `boolean` | `false` | the initial open state, uncontrolled |
| `onOpenChange` | `(open: boolean, details: OpenChangeDetails) => void` | | every change, with its reason (`trigger-press`, `close-press`, `escape-key`, `outside-press`); called before the change, `details.cancel()` stops it |
| `onOpenChangeComplete` | `(open: boolean) => void` | | once an opening or a closing has finished its transitions (not on the first render, nor for an exit a reopening interrupted) |
| `actionsRef` (react) | `{ current: OverlayActions \| null }` | | receives `close()` (reason `imperative-action`) and `unmount()` (ends an exit now); Vue exposes them on the Root's template ref, Angular as the root directive's methods |
| `handle` | `DialogHandle<Payload>` | | connects Triggers rendered outside the Root ([detached triggers](/docs/guides/detached-triggers)) |
| `triggerId` | `string \| null` | | the active trigger's id, controlled together with `open` |
| `defaultTriggerId` | `string \| null` | `null` | the initial active trigger, uncontrolled |

### Trigger

| prop | type | default | description |
| --- | --- | --- | --- |
| `disabled` | `boolean` | `false` | a disabled trigger opens nothing |
| `handle` | `DialogHandle<Payload>` | | the handle of a Root this Trigger opens from anywhere, outside it |
| `payload` | `Payload` | | what the Root's content receives while this Trigger is the active one |
| `id` | `string` | generated | the Trigger's id: `triggerId` and the handle's `open(id)` name it |

### Portal

| prop | type | default | description |
| --- | --- | --- | --- |
| `container` (react, vue) | `Element` | `document.body` | where the Backdrop, the Viewport and the Popup go |
| `keepMounted` (react, vue) | `boolean` | `false` | keep the content rendered while closed (before the first opening and after an exit), `hidden` and `data-closed`; reopening shows the same elements |
| `options` (angular) | `Element \| { container?, keepMounted? }` | `{}` | the same two options: `*dialogPortal="{ keepMounted: true }"`, or `*dialogPortal="element"` for a container alone |

### Backdrop

| prop | type | default | description |
| --- | --- | --- | --- |
| `forceRender` | `boolean` | `false` | render the Backdrop of a nested dialog too (by default only the outermost dialog's covers the page) |

### Viewport

No props of its own.

### Popup

| prop | type | default | description |
| --- | --- | --- | --- |
| `initialFocus` | an element, a ref, or `false` | the first tabbable element | focused on open (`false`: the popup itself); Vue and Angular also take a getter |
| `finalFocus` | an element, a ref, or `false` | the trigger | focused on close (`false`: nothing moves) |

### Title

| prop | type | default | description |
| --- | --- | --- | --- |
| `id` (angular) | `string` | generated | the id the popup's `aria-labelledby` points at; React and Vue take it as a plain attribute |

### Description

| prop | type | default | description |
| --- | --- | --- | --- |
| `id` (angular) | `string` | generated | the id the popup's `aria-describedby` points at; React and Vue take it as a plain attribute |

### Close

No props of its own.

## State and part attributes

| part | attributes |
| --- | --- |
| Trigger | `aria-haspopup="dialog"`, `aria-expanded` (`"true"` on the active trigger while open), `aria-controls` (the popup, on the active trigger while open), `data-popup-open` (the active trigger), `data-disabled`, an `id` |
| Backdrop | `aria-hidden="true"`, `data-open` / `data-closed`, `data-starting-style`, `data-ending-style`, `data-nested`, `data-nested-dialog-open`; `hidden` while kept mounted and closed |
| Viewport | `role="presentation"`, `data-open` / `data-closed`, `data-starting-style`, `data-ending-style`, `data-nested`, `data-nested-dialog-open`; `hidden` while kept mounted and closed |
| Popup | `role="dialog"`, `aria-modal="true"`, `aria-labelledby`, `aria-describedby`, `tabindex="-1"`, `data-open` / `data-closed`, `data-starting-style`, `data-ending-style`, `data-nested`, `data-nested-dialog-open`, the inline `--nested-dialogs: <n>`; `hidden` while kept mounted and closed |
| Title, Description | an `id` (generated unless given) |

## Keyboard

| key | action |
| --- | --- |
| Enter, Space on the Trigger | opens |
| Tab, Shift+Tab | the next or previous tabbable element of the popup, wrapping |
| Escape | closes (only the topmost layer, when one is open inside) |
