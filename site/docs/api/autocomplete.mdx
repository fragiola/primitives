A free-text input with a list of suggestions (the APG
[combobox pattern](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/) with list autocomplete;
Base UI's Autocomplete). **The value is the text**: a suggestion fills the input, and any other
text is a value too. A value that must be one of the items is a
[Combobox](/docs/api/combobox)'s.

<Example id="autocomplete" />

## Behaviour

- **`mode`**: the APG's four autocomplete behaviours, named as Base UI does: `list` (the list
  follows the text; a highlight leaves the text as it is), `both` (the list follows the text and
  the input completes inline), `inline` (inline completion over a fixed list), `none` (a fixed
  list, the text unchanged).
- **Inline completion** (`both`, `inline`, the APG's): typing a character highlights the first
  suggestion that starts with the text and shows it in the input, the part not typed selected, so
  the next character replaces it; a deletion removes it; the arrows show the highlighted
  suggestion; leaving the input accepts it (reason `input-blur`); Escape drops it.
- **Filtering** is Combobox's: a locale-aware "contains" (`filter`, `null` for none), `limit`,
  groups; `items` may change at any time (suggestions loaded as the text changes), and a
  highlight whose suggestion is gone is dropped.
- **Opening**: typing opens the list, an empty text closes it; a press on the input opens it only
  with `openOnInputClick`; ArrowDown opens on the first suggestion. `autoHighlight` highlights the
  first suggestion after typing (`list`, `none`).
- **Escape** closes the list, then clears the text. **Enter** chooses the highlighted suggestion,
  or, with none, closes the list and lets the form submit.
- **Focus**: DOM focus stays on the input; the highlighted suggestion is announced with
  `aria-activedescendant`. Disabled suggestions are highlighted, never chosen.
- **Forms**: the Input is the form control (`name`, `required`, its own validity), with no hidden
  input. A form reset returns an uncontrolled autocomplete to `defaultValue`. In a
  [Field](/docs/api/field), the Input takes the field's ids and states.
- **Shared with Combobox**: through each framework's shared code and the toolkit, never through
  Combobox's entry, so an app with Autocomplete alone ships no Combobox code.

## Anatomy

| part | element | `data-primitives-part` | role |
| --- | --- | --- | --- |
| Root | none | | holds the state |
| InputGroup | `div` | `autocomplete-input-group` | holds the Input and its buttons, and anchors the list |
| Input | `input` | `autocomplete-input` | the `combobox`; keeps DOM focus; the form control |
| Trigger | `button` | `autocomplete-trigger` | toggles the list; not in the tab order |
| Clear | `button` | `autocomplete-clear` | empties the text; rendered only while there is text |
| Value | none | | renders the value: the text, or a render function of it |
| Status | `div` | `autocomplete-status` | a polite live region for the consumer's text |
| Portal | none | | moves the Positioner to the end of `body` |
| Positioner | `div` | `autocomplete-positioner` | places the popup under the anchor |
| Popup | `div` | `autocomplete-popup` | the floating container |
| Empty | `div` | `autocomplete-empty` | a polite live region; its children show only while the list is empty |
| List | `div` | `autocomplete-list` | the `listbox` |
| Group | `div` | `autocomplete-group` | a `group` of suggestions |
| GroupLabel | `div` | `autocomplete-group-label` | names its Group |
| Separator | `div` | `autocomplete-separator` | between groups |
| Item | `div` | `autocomplete-item` | an `option`: a suggestion |

## Usage

<Framework name="react">

```tsx
import { Autocomplete } from "@fragiola/primitives-react/autocomplete";

<Autocomplete.Root items={CITIES} name="city">
    <label htmlFor="city">City</label>
    <Autocomplete.InputGroup>
        <Autocomplete.Input id="city" />
        <Autocomplete.Clear aria-label="Clear city">×</Autocomplete.Clear>
    </Autocomplete.InputGroup>
    <Autocomplete.Portal>
        <Autocomplete.Positioner sideOffset={4}>
            <Autocomplete.Popup>
                <Autocomplete.Empty>No city found.</Autocomplete.Empty>
                <Autocomplete.List>
                    {(city: string) => (
                        <Autocomplete.Item key={city} value={city}>
                            {city}
                        </Autocomplete.Item>
                    )}
                </Autocomplete.List>
            </Autocomplete.Popup>
        </Autocomplete.Positioner>
    </Autocomplete.Portal>
</Autocomplete.Root>;
```

</Framework>

<Framework name="vue">

```vue
<template>
    <Autocomplete.Root v-model:value="city" :items="CITIES" mode="both" name="city">
        <Autocomplete.InputGroup>
            <Autocomplete.Input id="city" />
        </Autocomplete.InputGroup>
        <Autocomplete.Portal>
            <Autocomplete.Positioner :side-offset="4">
                <Autocomplete.Popup>
                    <Autocomplete.Empty>No city found.</Autocomplete.Empty>
                    <Autocomplete.List v-slot="{ entry }: { entry: string }">
                        <Autocomplete.Item :key="entry" :value="entry">{{ entry }}</Autocomplete.Item>
                    </Autocomplete.List>
                </Autocomplete.Popup>
            </Autocomplete.Positioner>
        </Autocomplete.Portal>
    </Autocomplete.Root>
</template>
```

The List's default scoped slot gets `{ entry, index }`; the Value's, `{ value }` (the text).

</Framework>

<Framework name="angular">

```ts
@Component({
    imports: [AutocompleteRoot, AutocompleteInputGroup, AutocompleteInput, AutocompletePortal, AutocompletePositioner, AutocompletePopup, AutocompleteEmpty, AutocompleteList, AutocompleteItem],
    template: `
        <ng-container autocompleteRoot [items]="cities" name="city" [(value)]="city">
            <div autocompleteInputGroup><input autocompleteInput id="city" /></div>
            <ng-container *autocompletePortal>
                <div autocompletePositioner [sideOffset]="4">
                    <div autocompletePopup>
                        <div autocompleteEmpty>No city found.</div>
                        <div autocompleteList #list="autocompleteList">
                            @for (city of list.entries(); track city) {
                                <div autocompleteItem [value]="city">{{ city }}</div>
                            }
                        </div>
                    </div>
                </div>
            </ng-container>
        </ng-container>
    `,
})
export class CitySearch {
    protected readonly cities = CITIES;
    protected readonly city = signal("");
}
```

There is no Value directive: the Root's `value()` signal, read through `exportAs`
(`#autocomplete="autocompleteRoot"`), gives the text; `*autocompleteClear` is structural.
`injectAutocomplete()` gives a child component the Root.

</Framework>

it forwards. The names below are React's; Vue binds them the same way (`v-model:value`,
`v-model:open`), and Angular as inputs and outputs (`[(value)]`, `[(open)]`,

## Keyboard

| key | action |
| --- | --- |
| typing | changes the text and filters; opens the list (an empty text closes it) |
| ArrowDown / ArrowUp | closed: opens on the first (last) suggestion; open: the next (previous), then back to the input |
| Alt+ArrowDown / Alt+ArrowUp | opens without highlighting / closes |
| Enter | chooses the highlighted suggestion; with none, closes the list and lets the form submit |
| Escape | open: closes the list, the text kept; closed: clears the text |
| Tab | closes the list and moves on (`both`, `inline`: accepts the completion) |
