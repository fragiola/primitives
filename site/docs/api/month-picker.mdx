A trigger and a non-modal popup holding a [MonthCalendar](/docs/api/month-calendar): the
[DatePicker](/docs/api/date-picker)'s trigger, popup, form and Field, with a month as its value. Its
parts are the DatePicker's, named `month-picker-*`; the MonthCalendar inside the Popup has no value of its own and
**binds** to the picker. The popup is a non-modal APG
[dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/) disclosed by a button, as the
DatePicker's. It renders no text: the trigger's content and the popup's name are yours.

<Example id="month-picker" />

## Behaviour

- **Open, choose, close**: as the [DatePicker's](/docs/api/date-picker#behaviour): the calendar
  focuses its focused month as the popup opens (the value, else the month holding today);
  choosing a month sets the value, closes the popup (reason `item-press`) and focuses the
  Trigger; Escape, an outside press and Tab out close it; focus is not trapped.
- **Forms**: with a `name`, the Root renders a hidden input after its children, which submits
  `expiry=2026-11`, or an empty value. `required`, `disabled`, `readOnly`, a form reset and a
  [Field](/docs/api/field) work as the DatePicker's.

## Anatomy

| part | element | `data-primitives-part` | role |
| --- | --- | --- | --- |
| Root | none | | holds the value and the open state |
| Trigger | `button` | `month-picker-trigger` | toggles the popup, and anchors it |
| Portal | none | | moves the Positioner to the end of `body` |
| Positioner | `div` | `month-picker-positioner` | places the popup next to the trigger |
| Popup | `div` | `month-picker-popup` | the non-modal dialog, holding a `MonthCalendar.Root` |
| (hidden input) | `input` | `month-picker-input` | what the form submits |

## Usage

<Framework name="react">

```tsx
import { MonthPicker, type PlainYearMonth } from "@fragiola/primitives-react/month-picker";
import { MonthCalendar } from "@fragiola/primitives-react/month-calendar";

<MonthPicker.Root value={value} onValueChange={setValue} name="month">
    <MonthPicker.Trigger>{/* the formatted value */}</MonthPicker.Trigger>
    <MonthPicker.Portal>
        <MonthPicker.Positioner>
            <MonthPicker.Popup aria-label="Choose month">
                <MonthCalendar.Root>{/* its header and grid */}</MonthCalendar.Root>
            </MonthPicker.Popup>
        </MonthPicker.Positioner>
    </MonthPicker.Portal>
</MonthPicker.Root>;
```

</Framework>

<Framework name="vue">

```vue
<template>
    <MonthPicker.Root v-model:value="value" name="month">
        <MonthPicker.Trigger><!-- the formatted value --></MonthPicker.Trigger>
        <MonthPicker.Portal>
            <MonthPicker.Positioner>
                <MonthPicker.Popup aria-label="Choose month">
                    <MonthCalendar.Root><!-- its header and grid --></MonthCalendar.Root>
                </MonthPicker.Popup>
            </MonthPicker.Positioner>
        </MonthPicker.Portal>
    </MonthPicker.Root>
</template>
```

</Framework>

<Framework name="angular">

```ts
@Component({
    imports: [MonthPickerRoot, DatePickerTrigger, DatePickerPortal, DatePickerPositioner, DatePickerPopup, MonthCalendarRoot /* , its parts */],
    template: `
        <ng-container monthPickerRoot [(value)]="value" name="month">
            <button datePickerTrigger><!-- the formatted value --></button>
            <div *datePickerPortal datePickerPositioner>
                <div datePickerPopup aria-label="Choose month">
                    <div monthCalendarRoot><!-- its header and grid --></div>
                </div>
            </div>
        </ng-container>
    `,
})
```

The DatePicker's part directives serve it, re-exported from this entry.

</Framework>

## Props

Every part also takes what the [primitive contract](/docs/concepts/primitive-contract) gives. Vue
binds `v-model:value` and `v-model:open`; Angular `[(value)]`, `[(open)]`, `(valueChangeDetails)`,
`(openChangeDetails)`. The other parts' props are the [DatePicker's](/docs/api/date-picker#props).

### Root

| prop | type | default | description |
| --- | --- | --- | --- |
| `value` | `PlainYearMonth \| null` | | the chosen month, controlled |
| `defaultValue` | `PlainYearMonth \| null` | `null` | the initial month, uncontrolled |
| `onValueChange` | `(value: PlainYearMonth \| null, details: { reason }) => void` | | every choice (reason `item-press`), a form reset (`none`) |
| `open` | `boolean` | | the open state, controlled |
| `defaultOpen` | `boolean` | `false` | the initial open state, uncontrolled |
| `onOpenChange` | `(open: boolean, details: OpenChangeDetails) => void` | | every change, with its reason; called before the change, `details.cancel()` stops it |
| `onOpenChangeComplete` | `(open: boolean) => void` | | once an opening or a closing has finished its transitions |
| `actionsRef` (react) | `{ current: OverlayActions \| null }` | | receives `close()` and `unmount()`; Vue exposes them on the Root's template ref, Angular as the root directive's methods |
| `min` | `PlainYearMonth \| null` | | passed to the bound calendar |
| `max` | `PlainYearMonth \| null` | | passed to the bound calendar |
| `isUnavailable` | `(month: PlainYearMonth) => boolean` | | passed to the bound calendar |
| `locale` | `string` | the document's `lang` | passed to the bound calendar |
| `calendar` | `CalendarSystem` | the ISO calendar | a [calendar system](/docs/api/toolkit#calendar-systems), passed to the bound calendar: the values are its months, submitted as the first day's ISO date with the system (`2026-10-23[u-ca=persian]`) |
| `columns` | `number` | `3` | passed to the bound calendar |
| `name` | `string` | | the hidden input's form name (a Field's wins) |
| `required` | `boolean` | `false` | a native form's validation blocks a submission with no value |
| `disabled` | `boolean` | `false` | the Trigger cannot open the popup; nothing is submitted |
| `readOnly` | `boolean` | `false` | the popup still opens; its calendar chooses nothing |

### Trigger

No props of its own.

### Portal

| prop | type | default | description |
| --- | --- | --- | --- |
| `container` (react, vue) | `Element` | `document.body` | where the Positioner goes |
| `keepMounted` (react, vue) | `boolean` | `false` | keep the content rendered while closed (before the first opening and after an exit), `hidden` and `data-closed`; reopening shows the same elements |
| `options` (angular) | `Element \| { container?, keepMounted? }` | `{}` | the same two options: `*datePickerPortal="{ keepMounted: true }"`, or `*datePickerPortal="element"` for a container alone |

### Positioner

| prop | type | default | description |
| --- | --- | --- | --- |
| `side` | `"top" \| "bottom" \| "inline-start" \| "inline-end" \| "left" \| "right"` | `"bottom"` | the side of the trigger |
| `align` | `"start" \| "center" \| "end"` | `"start"` | the alignment along that side |
| `sideOffset` | `number` | `0` | the distance from the trigger, in px |
| `alignOffset` | `number` | `0` | the shift along its edge, in px |
| `collisionPadding` | `number` | `8` | the space kept from the viewport's edges, in px |
| `anchor` | `Element` | the trigger | the element to place the popup next to |

### Popup

No props of its own.

## State and part attributes

The [DatePicker's](/docs/api/date-picker#state-and-part-attributes), named `month-picker-*`; the hidden
input's value is the ISO text (`expiry=2026-11`).

## Keyboard

The [DatePicker's](/docs/api/date-picker#keyboard), with the [MonthCalendar's](/docs/api/month-calendar#keyboard) keys in the popup.
