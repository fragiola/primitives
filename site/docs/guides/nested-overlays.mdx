An overlay opened from inside another one is its **child**: a Popover opened from a Dialog, a
Menu opened from that Popover, a submenu of that Menu. Together the open overlays of a page form a
tree, whatever the DOM position of their portals (each one is portaled to the end of `body`).
Every overlay follows it: Dialog, AlertDialog, Drawer, Popover, Menu and its submenus,
ContextMenu, NavigationMenu and its nested levels, Select, Combobox and the date pickers. Nothing needs configuring: put a Trigger inside a popup and
its overlay is that popup's child.

## How the tree behaves

- **The parent** is decided when an overlay opens: the newest open overlay that contains one of
  its Triggers, else the one that contains the focused element, else none.
- **Escape** closes the newest overlay only. The next Escape closes the next one, and focus goes
  back to each level's trigger.
- **A press** keeps open the deepest overlay that contains it and its ancestors, and closes every
  other open overlay, newest first (reason `outside-press`). In a Dialog → Popover → Menu chain, a
  press inside the Popover (outside the Menu) closes the Menu and its submenus; a press on the
  Dialog closes the Popover and the Menu; a press on the Dialog's backdrop closes everything.
  A Dialog or AlertDialog makes the page under it inert, so a press outside it counts as a press
  in the overlay it was opened from: a Dialog opened from a Menu that stays open closes alone, and
  an AlertDialog opened from a Popover keeps both open.
- **Focus**: a Dialog's focus trap and a Popover's focus-out watch accept focus inside their
  descendants, so tabbing in a menu opened from a dialog never leaves the dialog.
- **Closing an overlay closes the overlays opened from it** (reason `none`).
- A Tooltip is no layer: Escape closes it first, and the overlay around it stays open.

## Nested dialogs

A Dialog (or an AlertDialog) whose Root is inside another dialog's Popup is **nested** in it. The
parts say so, for your styles:

| attribute | on | while |
| --- | --- | --- |
| `data-nested` | the nested dialog's Popup, Backdrop and Viewport | always |
| `data-nested-dialog-open` | the parent's Popup, Backdrop and Viewport | a dialog nested in it is open |
| `--nested-dialogs: <n>` | the parent's Popup (inline style) | the number of open dialogs nested below it, as a chain: `2` for a child open with its own child open, `0` when none |

A nested dialog's Backdrop renders nothing unless `forceRender`: the outermost backdrop already
covers the page. A press on a nested dialog's Viewport (or Backdrop) outside its Popup closes that
dialog only, since the press is inside its parent. Escape closes one level at a time.

```css
[data-primitives-part="dialog-popup"] {
    scale: calc(1 - 0.05 * var(--nested-dialogs));
    translate: 0 calc(-1rem * var(--nested-dialogs));
    transition: scale 150ms, translate 150ms;
}
[data-primitives-part="dialog-popup"][data-nested-dialog-open]::after {
    content: "";
    position: absolute;
    inset: 0;
    background: rgb(0 0 0 / 0.1);
    border-radius: inherit;
}
```

## Building your own

The tree is the toolkit's `/layers` entry, used through `/overlay`
([the DOM toolkit](/docs/api/toolkit)): `pushLayer(doc, { owner, backdrops, onParentClose, ... })`
resolves a layer's parent from its `owner()` elements, and `openOverlaySession` dismisses with
`dismiss(reason, event)`, `reason` `none` and no event when the parent closed.
